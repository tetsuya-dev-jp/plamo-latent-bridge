\section{Reproduction and recorded settings}
\label{sec:settings}

The experiment implementation is versioned at Git commit
\texttt{a2f72d5} (full revision in the execution record).
The final plotting changes and isolated capacity-diagnostic script are versioned
at \texttt{5becef5}; primary training and
answer-generation code is unchanged between these commits.
The execution record, upstream revisions and measured environment are stored in
\path{results/main/provenance/}.
Generated questions, raw predictions, fitted-run histories, selected-epoch metadata
and result-driven figures are included in the repository.
Upstream weights and source-feature caches are downloaded or generated locally.
The public code license does not replace the upstream model or MGSM licenses.

The full experiment is run from the repository root:
\begin{verbatim}
bash scripts/run_full_experiment.sh
\end{verbatim}
The script generates the fixed data, extracts source states, generates actual
translations, evaluates the frozen textual systems, trains all fitted conditions,
evaluates their held-out outputs and produces the summary and figures.
The project README describes environment preparation and individual commands.
The separate resubstitution diagnostic is reproduced with
\texttt{bash scripts/run\_overfit\_diagnostic.sh}.
The isolated smoke command and offline test suite are:
\begin{verbatim}
.venv/bin/python -m plamo_bridge --config configs/smoke.json \
  smoke --regenerate-data --overwrite
.venv/bin/python -m pytest
\end{verbatim}

The implementation was produced with DeepSeek V4.1 Flash.
Tests check arithmetic references and canonical split keys, valid-token pooling,
prompt and answer boundaries, causal loss alignment, bridge gradients with frozen
target parameters, variable-length batched generation, fractional seed averages,
and feature/translation cache provenance.
A real-model GPU smoke verifies the complete source-to-target path.
These checks establish implementation properties; task performance comes from
the separate full evaluations reported above.

Table~\ref{tab:settings} lists the fixed settings and their canonical records.
Selected epochs, losses, wall times and peak allocated memory are recorded per
run rather than inferred from the nominal configuration.
Timing scopes distinguish model loading, source extraction, translation and target
answer generation.
They describe this implementation on this host, rather than a calibrated hardware
benchmark or a general deployment latency claim.
